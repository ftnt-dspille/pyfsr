pyfsr.api.content_hub¶

Content Hub discovery — client.content_hub.

Search and discover installable content (connectors, solution packs, widgets, and — on 8.0.0+ — AI agents) from Fortinet’s Content Hub at repo.fortisoar.fortinet.com. Use this to find what is available to install on an appliance. For no-appliance discovery and direct artifact download, see pyfsr.repo.

Every content type is served by one catalog endpoint and discriminated by its type field; ContentType enumerates them.

get_installed_ai_agent(name_or_label: str) → pyfsr.models.AIAgent[source]¶

Resolve one installed AI agent by exact name or label.

Unlike the fuzzy search_*/find_* methods (which also match on description and would happily return a near-miss), this matches exactly — use it when the identity of the agent matters, e.g. resolving the agent an export template references. name is the agent id ("conversation"); label its display name ("Chat Assistant"). name wins a tie.

Requires FortiSOAR 8.0.0+.

Parameters:

name_or_label – the agent’s exact name or label.

Raises:

ValueError – if no installed agent matches exactly.

connector_versions(name: str) → pyfsr.models.ConnectorVersionInfo[source]¶

Return all published versions of a connector from Fortinet’s public repo.

Searches the local solutionpacks API for name (fuzzy — partial matches work), then follows the infoPath on the best-matching cloud record to fetch {repo}/latest/info.json. That public endpoint requires no authentication and returns availableVersions listing every version ever published.

name is a connector slug or partial name (e.g. "code-snippet" or "code"). Raises ValueError if nothing cloud-backed is found (box may not have FDN access, or name doesn’t match any connector).

Returns the full info.json payload as a dict-compatible ConnectorVersionInfo (availableVersions, operations, releaseNotes, etc.).

Example:

info = client.content_hub.connector_versions("code-snippet")
print(info.availableVersions)        # or info["availableVersions"]
# ['1.2.0', '1.2.1', ..., '2.2.1']
updates(types: str | list[str] | tuple[str, Ellipsis] | None = None, search: str = '', *, include_development: bool = False) → list[ContentUpdate][source]¶

Installed items with a newer version on the Content Hub.

The same query the Content Hub page runs with Update available ticked: installed = true and latestAvailableVersion set, excluding development connectors (pass include_development=True to keep them). types is any of "solutionpack", "connector", "widget" (default: all three). latestAvailableVersion is only as fresh as the box’s last Content Hub sync (pyfsr appliance content-hub sync). Returned in the order update_all() would apply them.

running_installs(*, max_age: float = RUNNING_JOB_MAX_AGE) → list[dict[str, Any]][source]¶

Import jobs running on the box now (any source: Content Hub, Import Wizard, another session).

A job counts when its status is not finished (or parked in Reviewing) and it changed in the last max_age seconds; older unfinished jobs are abandoned and would otherwise block forever.

wait_until_idle(*, timeout: float = 900.0, interval: float = 10.0) → None[source]¶

Block until no import job is running; ContentUpdateError after timeout.

FortiSOAR runs one import at a time; starting another while one runs corrupts or stalls both, so every update waits here first.

update(item: str | ContentUpdate, *, type: str | None = None, version: str | None = None, build_number: int | str | None = None, wait: bool = True, interval: float = 5.0, timeout: float = 900.0, check_compatibility: bool = True) → UpdateResult[source]¶

Update one installed item, the way the Content Hub Update button does.

POST /api/3/solutionpacks/update {"name", "version"} for every type (pack, connector, widget), then polls the import job. item is a name or label, or a ContentUpdate from updates(); version defaults to its latestAvailableVersion.

Refused before sending (ContentUpdateError), as the GUI does: while a module publish is running, and for a pack whose update needs a newer FortiSOAR than this box (check_compatibility=False skips that).

No backup is taken. For a connector, the result reports how many configurations it had before and after, and the message says so if the update dropped any (to change a connector’s version with a config backup and restore, use client.connectors.ensure_version).

update_all(types: str | list[str] | tuple[str, Ellipsis] | None = None, *, names: list[str] | None = None, dry_run: bool = False, stop_on_error: bool = False, **kwargs: Any) → list[UpdateResult][source]¶

Apply every available update (or those in names), one at a time.

Order: solution packs first, each after the packs it depends on; then connectors; then widgets. After the packs, the list is re-read so an item a pack already brought up to date is not updated twice. dry_run returns the plan without sending anything. Other keyword arguments go to update(). A refused or failed item is recorded and the run moves on, unless stop_on_error.

Strictly one install at a time: each update waits for any running import (from the GUI or elsewhere) to finish before starting, and waits for its own import job to finish before the next begins. wait=False is rejected. If an item’s job is still running at timeout, or the box stays busy, the run stops there rather than overlapping installs.
